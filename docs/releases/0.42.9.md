# Codex Lens 0.42.9

Prepared development build; not published as a GitHub release. Its changes are included in 0.43.0.

## Changed

- Show one aggregate history progress bar across all known session journals, weighted by their byte sizes. Keep the current file counter below it, move its name to a tooltip, and show the opening stage out of four. New descendants and growing journals update the measured totals; missing bounds remain indeterminate.
- Keep the component fixture gallery and its Development menu in Debug builds only. Release packaging and installer validation reject test names as well as QA bundle identifiers and environment overrides.

## Also included since 0.41.0

- Preserve the timeline, selection, filters and reading position when opening tabs, using Back or inspecting items in an independent window.
- Add session activity charts for events, tool and MCP calls, requested file changes, errors, waits and compactions, with linked period inspection and accessible values. Counts use bars or discrete marks according to data density; cumulative totals use steps.
- Keep timeline event colors visible across zoom levels and restore its viewport without empty margins.
- Cache validated session metadata, share overlapping reads and display recorded agent roles, descriptions, model settings and links to original instructions.
- Simplify the session picker, keep its loading surface consistent, align event rows and use measured progress with cancellation.
- Default new installations to English and Dark appearance, preserve saved choices and keep control accents consistent.
- Add signed in-app updates from GitHub and a reviewed uninstall flow that preserves local data by default.

## Installation and compatibility

Download `CodexLens-0.42.9-arm64.dmg` and drag Codex Lens to Applications. The app ZIP is an alternative; the symbols ZIP, checksums and metadata accompany the download.

This prepared build targets Apple Silicon on macOS 14 or later. It contains the production app, without QA paths or a forced fixture session. Normal launches use the local Codex installation and its existing connection. English and Dark appearance are the defaults for new installations.

The community app uses ad hoc code signing and is not Apple-notarized. macOS may require first-launch approval in Privacy & Security. Sparkle update signatures authenticate updates separately; they do not provide Apple notarization.

See the [documentation for this version](https://github.com/wolf75222/CodexLens/blob/v0.43.0/README.md#requirements-and-boundaries) for platform, Codex adapter and signing limits, and the [release process](https://github.com/wolf75222/CodexLens/blob/v0.43.0/docs/RELEASING.md) for validation details. A changelog entry does not establish interactive or live-service qualification.
